Start with the [quickstart](docs/site/quickstart.md), [integration guide](docs/site/integration.md),
[local UI](docs/site/local-ui.md), [AI suggestions](docs/site/ai-suggestions.md) and

Review diagnostic output before sharing it.

## Bugs, questions and proposals

After GitHub publication, use repository issues for reproducible bugs, focused feature
proposals and usage questions. Use the matching template and synthetic examples. Discussions
may be enabled later; there is no existing forum, chat server or commercial support desk.
While the repository is local, use your existing collaboration channel with the owner.

Include commands, package/commit and dependency versions, OS/Python, selected mode,
execution status/error code, expected behavior and a minimal reproduction. Provider outages,
account balances and model access belong to the provider; Fail2Test can help explain its
request/error handling but cannot grant quota or guarantee free availability.

The initial maintainer handles support as capacity permits. No response time, maintenance
contract, paid priority or support entitlement is promised. Do not post duplicate reports
or tag unrelated people to accelerate a response.

## Conduct and private contact

Follow [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md). For abusive conduct on GitHub, use
[GitHub's reporting process](https://docs.github.com/en/communities/maintaining-your-safety-on-github/reporting-abuse-or-spam):
choose **Report content** on the relevant comment/issue or **Block or Report → Report abuse**
on a profile. Submit sensitive details through GitHub's reporting form, not an ordinary issue.
The recipient is GitHub Support, which assesses its own platform policies. Reporting a
project-code violation does not guarantee platform action or notify the project maintainer.

The project currently has one human maintainer, no independent conduct panel and no separate
private conduct mailbox or mediation service. The maintainer can moderate visible repository
activity; private project review and independent internal adjudication are not available.
Concerns involving the maintainer can use the same GitHub platform route. A dedicated project
channel may be added later with consenting recipients. Do not infer an enforcement email
from commit authors or the upstream code-of-conduct authors. During local collaboration,
the owner and collaborator can continue using their existing private channel.
