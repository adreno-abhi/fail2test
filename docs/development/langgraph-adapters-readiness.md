# Native LangGraph adapter step

Approved by the project owner on 26 October 2026. Scope: native model/tool adapters, one realistic existing-graph example, conformance tests and documentation. No provider access, publication, or next feature is included.

## Stage 1 — PASS

Existing core transports and the graph-factory helper are implemented. The new adapters replace injected dependencies while preserving ordinary LangChain chat/tool interfaces. Case fixtures remain the source of controlled responses; reviewed rules remain the source of intended behavior. Original tool bodies are never called by the fixture wrapper. Executable application/schema code remains trusted; this is not sandboxing.

## Stage 2 — PASS

Build contract:

- `FixtureChatModel(context, slot="chat")` is a synchronous `BaseChatModel`, supports `invoke` and `bind_tools`, and uses versioned canonical chat requests.
- `fixture_tool(context, original_tool)` preserves the ordinary tool name/schema and serves fixture results instead of calling its body. Invalid/unsupported requests latch an incomplete outcome even when application code catches them.
- Chat helpers normalize supported messages and fixture responses. IDs/usage/response metadata generated by the framework are excluded; semantic tool-call IDs and message contents are preserved. Unknown semantic fields/options are rejected or retained explicitly, never silently dropped.
- Async/streaming/batched model calls and runtime-injected/advanced tool schemas remain explicitly unsupported in this step.
- `graph_runner` enforces serialized scheduling, permits controlled thread handoff for serial native tool execution, and serializes supported message state to JSON. Overlapping transport calls are rejected.
- A native `MessagesState`/`ToolNode` example keeps application graph construction unchanged while swapping model/tools in the test runner. The same case fails for duplicate effects and passes after deduplication.
- Add conformance tests for strict matching, copied tool bodies never running, invalid response/request handling, swallowed failures, thread handoff, and generated pytest with the example.
