# Fail2Test 0.1.0

Public source available since 28 October 2026. No tag, GitHub release or package
registry upload exists. This is the complete initial product within the scope below, with
an initial compatibility contract rather than a stable 1.0 promise.

## What it does

Turn a reproducible agent failure into a reviewed regression test that executes current
application code with recorded model/tool fixtures. The complete workflow is evidence
import → sanitization inspection → rule proposal/edit → explicit review → broken-baseline
reproduction → current-code regression → portable pytest export. A bundled local browser
UI and CLI use the same engine; no account, provider key, database or frontend build is
required for the default workflow.

- Import strict case JSON or supported neutral serial trace JSON, with completeness reports.
- Enforce tool call counts, argument bounds/equality/membership, forbidden tools, output
  conditions and call budgets. Missing/unsupported interactions cannot become green tests.
- Bind review and baseline records to exact case content; re-review after edits.
- Reduce inputs within execution budgets and review derived cases again.
- Integrate through an application-owned runner or supported native synchronous LangGraph
  chat/tool replacements. Export ordinary pytest that retains the Fail2Test runtime dependency.
- Optionally propose unapproved rules using trusted OpenRouter, compatible remote or
  already-running loopback model profiles, after exact request preview and explicit consent.

## Install and try

For the GitHub-first launch, install from a reviewed checkout. A PyPI upload is not promised;
do not assume `pip install fail2test` identifies this project's release.

```console
git clone https://github.com/adreno-abhi/fail2test.git
cd fail2test
uv sync --locked
uv run fail2test --help
```

The repository is public and the clone requires no GitHub account. Once a release tag is approved and created, use that tag or
the published exact commit to reproduce this candidate rather than assuming future `main`
is unchanged. Follow the [quickstart](../site/quickstart.md),
[evidence guide](../site/evidence.md), [UI walkthrough](../site/local-ui.md) and
[integration guide](../site/integration.md). Native dependencies are optional; see the guides.

## Supported scope and limits

- Python 3.12–3.14; verified Ubuntu 22.04 and Windows Server 2022 CI, with additional dated
  local results in the [compatibility record](../site/compatibility.md). Broader OS/browser,
  ARM and arbitrary dependency-version combinations are not claimed.
- Synchronous, serialized JSON fixture execution. Async, streaming, multimodal, overlapping
  calls and checkpoint/state restoration are unsupported. Evidence capture/conversion and
  dependency injection are developer responsibilities; no automatic vendor recorder exists.
- Fixtures test application handling of recorded responses. They do not evaluate changed
  prompts against live models or establish model quality. Unsupported execution stays incomplete.
- Sanitization is best effort. Inspect saved artifacts and provider previews before sharing.
  Trusted Python runners/plugins can access the machine and network; worker supervision is
  not a hostile-code sandbox. The UI is for explicit single-owner loopback use.
- Package version **0.1.0**, case schema **0.1**, neutral trace schema **0.1**. They are versioned
  separately. Preserve originals when migrating. Do not depend on undocumented private modules.
  Security maintenance targets the latest published version after launch; no older-version
  backport window or support SLA is promised.

No independent human onboarding timing, adoption, virality or willingness-to-pay measurement
is claimed. The owner confirmed the guided synthetic UI walkthrough; automated additional
application trials and installed acceptance have separate, explicitly limited evidence.
