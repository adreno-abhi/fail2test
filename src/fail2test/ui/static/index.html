FROM EVIDENCE TO CONFIDENCE

A failure worth
keeping as a test.

Inspect what happened, define what should happen, and run your current code against recorded model and tool responses.

  1. Import a JSON recording of a failed agent run: its input and model/tool requests and responses.
  2. Review the evidence and intended behavior.
  3. Reproduce the failure, verify the fix, export pytest.

The example records an agent requesting the same refund twice. Review the “refund once” rule, reproduce the broken behavior, then verify the fixed code. No API key or payment service is used.

Have your own failure? Choose “Import evidence” for accepted formats and preparation instructions.

This workspace has no failure.json example. To create a separate demo workspace, run fail2test init demo, then fail2test ui --workspace demo in your terminal.

Import evidence

                    
                

                

                    Upload a JSON recording of a failed agent run,
                    containing the original input and recorded model/tool requests
                    and responses. Fail2Test uses these responses as fixtures while
                    running your current application code.
                

                
                

                    What file should I upload?
                    
    
                        
  • Fail2Test case v0.1: a case JSON with
                            input, model/tool fixtures and behavioral rules. An
                            initialized demo includes failure.json;
                            an exported bundle includes case.json.
    • 
                        
  • Neutral trace v0.1: a JSON recording
                            with trace_schema_version,
                            trace_id, input,
                            completeness and paired request/result
                            events. You add and review rules after import.
    • 
                    

                    
Screenshots, plain error logs, repository ZIPs and arbitrary
                        provider trace exports are not supported uploads. Convert
                        your recording into one of these formats first; a stack
                        trace alone cannot supply the recorded responses.

                    
For your own application, configure a runner that injects
                        these fixtures into current code. Uploading JSON alone does
                        not connect Fail2Test to your application. Missing interactions
                        remain incomplete and cannot prove a fix.

                

                

                    Remove private data before uploading. Known sensitive values
                    are sanitized locally before saving; inspect the report after import.
